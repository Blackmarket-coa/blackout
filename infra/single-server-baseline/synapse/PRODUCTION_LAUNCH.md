# Synapse production launch profile (`theblackout.app`)

This profile sets Synapse identity as:

- `server_name`: `theblackout.app` (this is immutable after launch)
- `public_baseurl`: `https://matrix.theblackout.app/`

The split is intentional:

- Federation identity remains the apex domain (`@user:theblackout.app`).
- Client API is served from the Matrix subdomain behind reverse proxy.

## Non-default settings explained

- `server_name: theblackout.app`
  - Locks MXID namespace to the apex domain for launch and long-term federation.
- `public_baseurl: https://matrix.theblackout.app/`
  - Ensures invite links, media links, and client-discovery metadata point at the reverse-proxied Matrix API host.
- `max_upload_size: 100M`
  - Restricts upload abuse while still allowing practical media sharing.
- `max_image_pixels: 50M`
  - Mitigates image decompression-bomb behavior and memory spikes.
- `dynamic_thumbnails: true`
  - Enables on-demand thumbnailing for compatible client behavior.
- `enable_registration: false`
  - Closes public self-signup for launch-day anti-abuse.
- `enable_registration_without_verification: false`
  - Prevents accidental open registration posture if other flags change.
- `registration_shared_secret`
  - Allows controlled bootstrap account creation via admin tooling.
- `trusted_key_servers: [matrix.org]`
  - Keeps Synapse's standard trusted key server default unless an explicit alternative trust policy is adopted.
- `turn_uris` + `turn_shared_secret`
  - Integrates coturn with ephemeral TURN credentials generated by Synapse.
- `turn_user_lifetime: 1h`
  - Limits exposure window for leaked TURN credentials.
- `turn_allow_guests: false`
  - Avoids guest media relay abuse.
- `rc_message`, `rc_registration`, `rc_login`, `rc_joins`
  - Tightens rate limiting for launch while preserving normal usage bursts.

## First admin bootstrap checklist

1. Generate strong secrets and populate `.env`:
   - `SYNAPSE_REGISTRATION_SHARED_SECRET`
   - `SYNAPSE_MACAROON_SECRET_KEY`
   - `SYNAPSE_FORM_SECRET`
   - `TURN_STATIC_AUTH_SECRET`
2. Render `synapse/homeserver.yaml` from template with environment substitution.
3. Start `postgres`, `redis`, `synapse`, and `coturn`.
4. Create first admin with shared-secret registration:
   - `register_new_matrix_user -c /data/homeserver.yaml http://127.0.0.1:8008`
5. Disable/rotate the registration shared secret after bootstrap if not needed for ongoing operations.
6. Verify `.well-known` responses on `https://theblackout.app`.
7. Confirm TLS certificates include:
   - `theblackout.app`
   - `matrix.theblackout.app`
   - `turn.theblackout.app`
8. Enforce backup + restore drill for `/data`, media volume, and Postgres dump.

## Federation sanity checks

Run these checks after first deploy and after major upgrades:

1. Client versions endpoint:
   - `curl -fsS https://matrix.theblackout.app/_matrix/client/versions`
2. Federation versions endpoint:
   - `curl -fsS https://matrix.theblackout.app/_matrix/federation/v1/version`
3. Well-known server delegation:
   - `curl -fsS https://theblackout.app/.well-known/matrix/server`
   - Expect `{"m.server":"matrix.theblackout.app:443"}`
4. Well-known client discovery:
   - `curl -fsS https://theblackout.app/.well-known/matrix/client`
5. Federation tester:
   - Validate `theblackout.app` in Matrix federation tester and confirm no SRV/.well-known mismatches.
6. Cross-server handshake:
   - Join a public room hosted on another homeserver and verify timeline send/receive in both directions.
