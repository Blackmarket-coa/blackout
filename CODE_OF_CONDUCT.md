# Code of Conduct

Blackout adopts the [Contributor Covenant, version 2.1](https://www.contributor-covenant.org/version/2/1/code_of_conduct/),
which is the canonical text of this Code of Conduct. The Covenant defines
the standards we expect, the enforcement responsibilities of project
maintainers, the scope of the Code, and the enforcement guidelines. Read it
in full at the link above.

This document records the **Blackout-specific scope and reporting routes**
that the Covenant requires us to define.

## Scope

This Code applies to every space the project operates in, including:

- The `Blackmarket-coa/blackout` GitHub repository — issues, pull requests,
  reviews, Discussions, and the wiki.
- The hosted Matrix instance at `https://matrix.theblackout.app`, including
  `#welcome:theblackout.app`, `#blackout-dev:theblackout.app`, and every
  other room operated by the project.
- The launch **Coliseum Coalition** and any other Coalitions hosted on the
  project's homeserver.
- Any public space where an individual is representing the project — for
  example, posting on social media using a project handle, or speaking at
  events on behalf of the project.

## Reporting

We do **not** operate a dedicated reporting email address. Reports go through
one of two channels, depending on the nature of the report:

1. **GitHub Security Advisories**
   ([new advisory](https://github.com/Blackmarket-coa/blackout/security/advisories/new))
   for any report that involves a safety risk to a specific person — this
   path is private, has access controls, and is monitored by the security
   reviewers team.
2. **Direct message to a project maintainer** listed in
   [`.github/CODEOWNERS`](.github/CODEOWNERS) — on Matrix at
   `#blackout-dev:theblackout.app`, or via GitHub. Use this for general
   reports.

When reporting, include: what happened, where it happened (link if possible),
who was involved, and any context you can share. You do not need to have
proof — concerns are worth raising even when they're partial.

Reports are confidential. The handling maintainer will only share what is
needed to address the report.

## Distinction from security vulnerabilities

This Code of Conduct covers **conduct**. For **software vulnerabilities**
(exploitable bugs, key handling defects, supply-chain risks), see
[`SECURITY.md`](SECURITY.md), which describes the disclosure process. Posting
a working exploit publicly is itself a Code of Conduct violation and will be
treated as one in addition to whatever security response is required.

## Enforcement

The enforcement ladder defined in the Contributor Covenant 2.1 (Correction →
Warning → Temporary Ban → Permanent Ban) applies. The handling maintainer
will document which rung is being applied and why. Appeals are handled by a
maintainer other than the one who issued the action; raise an appeal through
the same reporting channels above.
