# Policy changelog

Every change to Blackout's **privacy and monetization commitments** is recorded
here, with an effective date and a link to the commit that made it. The git
history of this file is the audit trail: `git log -p docs/legal/CHANGELOG.md`
shows every commitment this project has ever made, when it changed, and who
changed it.

This is deliberately separate from the release changelogs. `/CHANGELOG.md` and
`/docs/changelogs/` are inherited from element-web and generated by `allchange`
from PR metadata — they describe **shipped code**. This file describes **promises
to users**, which change on their own schedule and must not be rewritten by a
tool. Do not put policy entries there, and do not put release notes here.

Entries are newest-first and dated by **effective date**, not merge date. See
[`policy-change-process.md`](policy-change-process.md) for how a change gets
made, and [`../../TRUST.md`](../../TRUST.md) for the user-facing summary of what
these commitments mean.

**Status of the underlying legal documents:** `privacy-policy.md` and
`terms-of-service.md` in this directory are **drafts, not yet in effect**, with
unfilled placeholders pending counsel review (see [`README.md`](README.md)). The
commitments recorded below are engineering and product commitments backed by
verifiable code; they are not a substitute for those documents, and nothing here
should be described as a published privacy policy until that review lands.

## 2026-08-10 — Initial record

The first entry. It establishes the current commitments as a baseline so that
every later change is visible as a diff against something. It is a _record_ of
existing behaviour, not a set of new promises: each item below links to code you
can check today.

### Privacy and encryption

-   **End-to-end encryption is never behind a paywall, on any tier, ever.**
    Verifiable: the complete catalogue of paid feature gating is the seven tier
    tables unioned in
    [`packages/blackout-protocol/src/entitlements/bundles.ts`](../../packages/blackout-protocol/src/entitlements/bundles.ts)
    — none of them contains an encryption key, so there is no mechanism by which
    encryption could be sold.

    This is the commitment most likely to come under commercial pressure, and the
    one this changelog exists to protect. Weakening it requires an entry here with
    a visible diff.

-   **Every private room and direct message is end-to-end encrypted by default.**
    Effective from this date; previously true only on some paths. Enforced by a
    required compiler-checked flag in the API and by
    [`pnpm guard:room-encryption`](../../tools/ci/check-room-encryption.mjs) in CI.
    See [the 2026-08-10 encryption audit](../audits/2026-08-10-encryption-audit.md)
    for what was broken and what changed.

-   **Some rooms are deliberately not encrypted, and we name them.** Publicly
    joinable rooms, and the service rooms the Blackout bot posts into (marketplace
    vendor/order/ledger rooms, `#bugs`, the standing public rooms). The bot has no
    Megolm implementation and cannot post into an encrypted room; encrypting these
    would break them rather than protect them. The current list is in
    [`TRUST.md`](../../TRUST.md) and changes to it belong in this changelog.

-   **No bot or moderation tool can read encrypted room content.** The server bot
    has no timeline-read capability at all — not restricted, absent.

-   **No server-side log, error report, or analytics captures message content.**
    There is no PostHog, Segment, or session-replay integration in the product.

-   **Calls and townhall media are not covered by message encryption today.**
    Transport is TLS; per-call media encryption is in progress. Recorded here
    because it is the kind of gap that is easy to leave out of marketing copy. See
    [`THREAT_MODEL.md`](../../THREAT_MODEL.md) §7 R2.

-   **Privacy-enhancing features beyond encryption are tiered.** Tor transport,
    decoy traffic, image perturbation, persona compartments, dead-drop anonymity
    padding and decoys, mesh transport, and active defense are paid. We say "E2EE
    is never paywalled", which is true; we do not say "privacy is never
    paywalled", which would not be.

### Monetization

-   **Nothing is being charged as of this date.** The monetization surface ships
    in a default-unlocked posture: the catalog is visible but every premium feature
    resolves as owned. Going live is a deliberate flip, gated on legal/compliance
    sign-off. See
    [`../operations/MONETIZATION_GO_LIVE.md`](../operations/MONETIZATION_GO_LIVE.md).

-   **Four tiers: Free, Signal, Coalition, Sovereign.** Free is a usable product,
    not a trial — baseline private encrypted communication with no expiry. Defined
    in
    [`consumerTiers.ts`](../../packages/blackout-protocol/src/entitlements/consumerTiers.ts).

-   **What paid tiers add is capability, not un-crippling.** Paid features are
    substantively different code paths, not switches that re-enable something
    already written. Stated in each entitlement family's own source.

-   **Prices are not defined in this repository.** The catalog lives in the Free
    Black Market service. Price changes are not policy changes and do not require
    an entry here; changing _what a tier is allowed to gate_ does.

-   **Self-service transparency and the warrant canary are free at every tier.**
    `GET /v1/transparency/me` and `GET /v1/transparency/canary`, the latter
    Ed25519-signed.

### Known gap recorded at this date

-   **Personal data export is currently gated.**
    `GET /v1/transparency/audit-export` returns HTTP 402 below the Coalition tier,
    and no free export path exists. This is inconsistent with a data-portability
    commitment, so no such commitment is claimed as of this entry. When a
    free self-service export ships, it lands here as a new entry.
