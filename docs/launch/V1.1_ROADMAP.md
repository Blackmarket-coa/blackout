## What V1.1 is

The first post-test-flight release, targeting **6–8 weeks after the V1
launch**. V1.1 stabilizes what V1 ships — it is not a "new features"
release. The substantive new-features release is V1.2.

## Inputs (these get summarized here at H84+)

V1.1 scope is drawn from five sources, in priority order:

1. **Coliseum findings.** All issues with `T-Coliseum-Finding` label and
   `severity:high` or `severity:critical`.
   ```bash
   gh issue list --label "T-Coliseum-Finding" --label "severity:high" --state open --json number,title,labels
   gh issue list --label "T-Coliseum-Finding" --label "severity:critical" --state open --json number,title,labels
   ```
2. **Priority-order proposal tally.** The ranked vote from challenge 06
   gives us the community's ordering across the 8 challenge domains. The
   top 3 domains get explicit V1.1 commitment.
3. **`Help Wanted` issues with traction.** Issues labeled `Help Wanted`
   that accumulated 5+ reactions or 3+ "me too" comments during the
   test flight.
4. **Roadmap-category Discussions.** All threads in the Roadmap Discussion
   category that have 5+ upvotes.
5. **Deferred workstreams.** Workstreams B–F from
   [`docs/architecture/deferred-bodies-schedule-2026-05-01.md`](../architecture/deferred-bodies-schedule-2026-05-01.md),
   re-evaluated against test-flight findings. Anything the test flight
   reinforced graduates; anything it disconfirmed stays deferred.

## Inclusion bar

An item makes V1.1 if **any one of the following** is true:

- It has 5+ reactions on its GitHub issue.
- 3+ distinct testers reported it via aid posts or Coliseum findings.
- A maintainer explicitly tags it `V1.1`.

## Out of V1.1 (explicit deferrals)

These were called out at planning time as **not** in V1.1 regardless of
test-flight outcomes:

- **In-app contributor badges.** The recognition mechanic during the test
  flight is repo-side (`docs/launch/spotlights/H{N}.md` + daily reports).
  In-app badges land in V1.2 alongside the broader recognition surface.
- **First-class Coliseum app feature.** The launch Coliseum is a *seeded
  Coalition* using existing primitives. A bespoke Coliseum UI feature is
  V1.2 work (or later, if the test flight doesn't surface enough demand to
  justify it).
- **Marketplace real-integration expansions.** FBM is the production-real
  marketplace. Other marketplace integrations stay as guarded placeholders
  until V1.2 at the earliest.
- **PQ-hybrid envelope inspector UI.** Tracked in challenge 08's
  governance proposal. The CRYPTO is in V1; the inspector AFFORDANCE is
  V1.1 territory only if challenge 08 generates enough demand.

## Why this is a stub

Three reasons:

1. **Until we run the test flight, we don't know what V1.1 should contain.**
   Filling this in now would be guessing.
2. **The daily build reports reference this file.** They need a path that
   exists so the links don't 404.
3. **Locking the structure now means the H84 fill-in is mechanical** rather
   than a design exercise during a fatigue window.
